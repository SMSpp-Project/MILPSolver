---------------------------------
Methods for building the problem
---------------------------------

Starting point is set_Block() that initializes CPLEX environment.
It uses a std::queue<Block*> to process the block and its children several times.

The first time, it counts the static and dynamic linear constraints and variables,
using:
- count_const() - renamed count_constraints()
- count_var() - renamed count_variables()

count_constraints() incremented a counter and was called only on LinearConstraints
Now it is called on FRowConstraints and the counter is incremented if FRowConstraint
contains a LinearFunction.

count_variables() was and is called on ColVariables only it incremented a
counter and used an calculated the number of total active constraints accumulating
lvar.get_num_active_const(). Now we cannot retrieve the number of active constraints
for a ColVariable so we retrieve the active stuff and we check if they are FRowConstraints.
Since we need the active Constraints for each ColVariable later, we keep them in a new vector.

------------------------

Now we have
- numcols (number of Variables)
- numrows (number of Constraints)
- nzelements (number of all the active Constraints aka non-zero elements)
We create the CPLEX arrays of the right size

-------------------------

The second queue processing is for filling constraint-related CPLEX arrays
(sense, rhs), and for filling four vectors that track between static/dynamic
Constraints pointers and indexes in the CPLEX arrays,
v_s_const_int[] and v_int_s_const[],
v_d_const_int[] and v_int_d_const[],
using:
- scan_s_const() - renamed scan_static_constraints()
- scan_d_const() - renamed scan_dynamic_constraints()

scan_static_constraints() was called only on LinearConstraints, now we call it
on RowConstraints and if they are not LinearFunctions we throw an exception.
It puts in the vectors v_s_const_int[] and v_int_s_const[] only the first Constraint
of a group of Constraints. To make this work we cannot have groups of mixed stuff
(No OneVarConstraints - we check them separately - and no FRowConstraints with
non-LinearFunction).
It is not changed much.

scan_dynamic_constraints() was called only on LinearConstraints, now we call it
on RowConstraints and if they are not LinearFunctions we throw an exception.
It is not changed much.

All the vectors for constraints are then sorted.

--------------------------
The third queue processing is for filling variable-related CPLEX arrays
(matbeg, matcnt, matind, matval) using:
- scan_s_var() - renamed scan_static_variables()
- scan_d_var() - renamed scan_dynamic_variables()

scan_static_variables() first filled lb and ub, this now needs to be done
elsewhere by scanning OneVarConstraints. Then it filled xctype, again is to be fixed.
Then it retrieved the active constraints for each ColVariable with old
lvar.get_num_active_const() and for each active Constraint it retrieved the
coefficient of the ColVariable. This is still done but now we cannot retrieve
directly the active constraints for each variable, so we use the new vector we
fill in count_variables(). Also, we have to retrieve the LinearFunction for
each FRowConstraint and get the Variable coefficients from that.

scan_dynamic_variables() same thing.
Moreover for each ColVariable we retrieve the coefficient of the objective function
two coefficients if the objective is a DQuadFunction, they are saved into objective[]
and q_objective[]. The code for this is changed a lot to reflect changes in
SMS++ interface. Not sure why this is done only for dynamic vars.
--------------------------
At this point we check the type of the Objective (eMin or eMax). This has to be
fixed as get_type() for functions does not exist.

All the vectors for variables are then sorted.
--------------------------
A fourth queue processing is fot checking Objective Functions and fill
objective[] and q_objective[] CPLEX arrays. I'm not sure that this is the
same thing done in scan_dynamic_variables().
The old version used scan_l_of on LinearObjectiveFunctions and
scan_q_of on DQuadObjectiveFunctions, now we have to get the function through
the Objective so I merged the two functions in scan_objective() that takes a
FRealObjective.
In the old version a DQuadObjectiveFunction had the get_v_var() and get_v_q_var()
methods, each one returned a vector of pairs <index, coeff>, now there is only
get_v_var() that returns a triple <index, lin_coeff, q_coeff>.
